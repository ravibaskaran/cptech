# Research: Pitfalls

## Pitfall 1: Writing A Generic CP App BRD

- **Warning signs**: BRD focuses on login, project list, lead form, dashboard, and notifications but does not explain CP sourcing, trust, payouts, disputes, employee controls, or RM operations.
- **Prevention**: Keep the CP network lifecycle as the organizing spine.
- **Phase**: Phase 1 and Phase 2.

## Pitfall 2: Confusing Manthan Baseline With Future CP Differentiation

- **Warning signs**: Requirements repeat what Manthan already has without identifying extension/configuration/source-of-truth needs.
- **Prevention**: Add a Manthan baseline section and a "reuse/configure/extend/add" classification for each capability.
- **Phase**: Phase 2.

## Pitfall 3: Vendor Comparison Becomes Procurement Opinion

- **Warning signs**: BRD declares a winner instead of mapping gaps in written proposals.
- **Prevention**: Use capability evidence, confidence tags, and "not specified in proposal" language.
- **Phase**: Phase 3.

## Pitfall 4: AI Dominates MVP Scope

- **Warning signs**: AI calling/campaign automation gets treated as core before lead ownership, site-visit proof, commission ledger, and CP activation are specified.
- **Prevention**: Keep AI as second-wave unless tied directly to activation, conversion, or trust.
- **Phase**: Phase 2 and Phase 4.

## Pitfall 5: CP Employee Lifecycle Is Underbuilt

- **Warning signs**: CP is treated as a single user, with no employee invite, role, lead assignment, exit, reassignment, or sub-agent attribution model.
- **Prevention**: Include separate CP owner, CP employee/agent, and CP telecaller flows.
- **Phase**: Phase 2.

## Pitfall 6: Compliance Is Treated As Document Upload Only

- **Warning signs**: RERA/GST/PAN/bank/KYC are only fields, not approval, expiry, renewal, exception, and audit workflows.
- **Prevention**: Add compliance lifecycle and operational exception requirements.
- **Phase**: Phase 2.

## Pitfall 7: No BRD Acceptance Criteria

- **Warning signs**: The BRD is long but not reviewable; no checklist can prove whether it is complete.
- **Prevention**: Define BRD completion criteria in requirements and roadmap success criteria.
- **Phase**: Phase 1.
